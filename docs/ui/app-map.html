好查经 · 界面地图 App Map

看图找编号，用编号说话。

这一页把好查经（内部名 ChaJing）所有看得见的界面都画出来，每个部件用框圈住、贴上一个短编号，旁边的表格写明这个编号叫什么、上面是什么字、按什么键、点了会怎样、在哪个源文件里。想改哪里，先在图上找到它，然后直接说编号，例如「把 SW4.3 的文字改掉」「RW1.3 换个图标」，两边说的就一定是同一个东西。

鼠标移到图上的框或表格里的行，另一边会同时亮起；点框跳到它在表里的那一行，点表里的编号跳回图。页面最后有全部编号的速查索引。

  • 实拍应用真实渲染的离屏截图（随系统深浅色切换）
  • 示意按源码文案手绘的示意，截不到图的系统界面
  • 实线框 = 一级部件
  • 虚线框 = 它里面的子部件
  • 橙色 = 正在指着的那个
  • 文案与源码一字不差（含空格）
  • {模板}运行时拼出来的文案
  • 系统由 macOS 提供，不在源码里

实拍图上的框不是手画的：位置取自 shots/manifest.json 里每个部件的 regions（由 make ui-shots 在离屏渲染时量出来），按截图尺寸换算成百分比，所以和真实布局一致，图缩放时框也跟着缩放。内容以 2026-09-18 的工作区源码为准，共 73 个编号。

  1. 中文输入法组字时按键被拦截SearchWindow.swift

    本地按键监听（SW7）在事件到达输入框之前就处理 esc、↑、↓、⏎，而且不检查输入框是否有未上屏的组字文本。用拼音输入法打「约」这类中文书名时，↑↓ 选候选、⏎ 上屏、esc 取消组字都会被应用截走。

  2. 点 Dock 图标只在没有可见窗口时才调出搜索AppDelegate.swift · README.md

    有阅读窗口开着时，点 EP1 只会激活应用。

  3. 第一条结果单击即打开，其余要点两次SearchView.swift

    点已选中的行（SW2.1）= 打开，而第一条默认就是选中的。同样是单击，结果不一致。

  4. 阅读窗口里没有办法复制经文SearchView.swift · ReaderWindow.swift

    经文 Text 没有启用文本选择，MB3.4 在阅读窗口里无事可做。复制只有 SW4.5 一条路，而且复制后没有任何反馈。

  5. 阅读窗口的翻章按钮缺少给 VoiceOver 的标签ReaderWindow.swift

    RW1.1 和 RW1.4 既没有悬停提示也没有给 VoiceOver 读的标签；只有 RW1.3 有 .help 提示。

  6. 搜索窗口的位置记忆不起作用SearchWindow.swift

    SW0 设置了 frame autosave，但每次显示都会重新居中到鼠标所在屏幕，实际只有窗口大小被记住。

  7. 输入框的 onSubmit 是死代码SearchView.swift · SearchWindow.swift

    ⏎ 已被按键监听吞掉，SW1 的 TextField onSubmit 不会触发。

  8. 状态栏菜单第一项的快捷键字样是固定文字（已不适用）AppDelegate.swift

    原来说的是 SM1 和 AW6 里提到一个可能不可用的快捷键。现在两处都只写 ⌥Space，而 ⌥Space 不需要权限、始终注册，这条不再成立。

命名规则：两个大写字母表示界面（EP 入口 · MB 主菜单栏 · SM 状态栏菜单 · SW 搜索窗口 · RW 阅读窗口 · AW 关于窗口 · SY 系统界面），后面的数字是部件，点号后面是它的子部件；0 号永远是窗口框架或整体。Wireflow 用单个字母加数字表示「状态」（S1、R2、D1…），这里用两个字母表示「部件」，两套编号不会撞车。

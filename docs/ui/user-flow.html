好查经 · 用户流程 (User Flow)

按任务画的流程图：一个人想办成一件事，要经过哪些步骤、在哪里分叉、可能停在哪里。

本文每张图对应一个用户目标，节点是抽象的「操作 / 判定 / 系统响应 / 结局」，不是截图。 有哪些窗口和菜单见 app-map.html，窗口之间怎样跳转见 wireflow.html。 所有行为都从 Sources/ChaJing/ 的源码读出，没有运行 App；界面文字按源码原样引用。 源码与 README 或界面提示有出入的地方，图里画的是源码的行为，出入列在文末。

流程 1首次启动与权限

目标：打开 App 就能查经；Space+P 组合键需要「辅助功能」权限，授权过程不挡住搜索窗口，也不用重启。

  • 启动顺序在 AppDelegate.applicationDidFinishLaunching：预载经文 → 主菜单 → 菜单栏图标（SF Symbol book.closed）→ 注册 ⌥Space → 尝试启动 Space+P → 刷新菜单标题 → 显示搜索窗口。无论是否授权，搜索窗口都会立刻出现，轮询在后台进行。
  • ⌥Space 用 Carbon RegisterEventHotKey（GlobalHotkey.swift），不需要任何权限。register() 的返回值被丢弃，热键被别的 App 占用时没有任何提示。
  • 未授权时调用 SpaceChordMonitor.requestPermission() 弹出系统提示，同时起一个 2 秒一次的 Timer 反复调用 chord.start()；用户在「系统设置 → 隐私与安全性 → 辅助功能」勾选好查经后，最多 2 秒监听就启动，定时器停止，菜单标题随之改变。启动时只弹系统提示，不会自己打开系统设置；如果用户当时点了「拒绝」，之后从菜单里那一项再进来（见下表和流程 7）。
  • 这个菜单项同时出现在菜单栏图标菜单和「好查经」菜单里，标题有三种（updateChordMenu()）：
条件菜单项标题点击后
监听正在运行停用 Space+P 快捷键停止监听
已授权，但监听没在运行启用 Space+P 快捷键启动监听
未授权开启 Space+P 快捷键（需授权辅助功能）…帮用户把它开起来：调用系统授权提示（系统只会弹一次），直接打开「系统设置 → 隐私与安全性 → 辅助功能」，并（重新）开始 2 秒一次的轮询，勾选后自动启动监听
  • 标题写的是「点了会怎样」，不是当前状态。它在启动时、轮询成功时、用户点击该菜单项时刷新，另外两个菜单每次打开都会经 menuNeedsUpdate 重新判断一次，启动后才授予或撤销权限，标题也不会错。菜单里没有单独通向系统设置的项，这件事由未授权状态下的这一项来做（openAccessibilitySettings()）。
  • 同在这两个菜单里的 关于好查经 打开一个独立的非模态窗口（AboutWindow.swift，440×500）：图标、好查经、版本行、作者写的 为什么做这个、作者 github.com/Lamonkey（点击后在浏览器打开 https://github.com/Lamonkey），底部两行小字是快捷键和经文来源。窗口里没有按钮，用红色关闭按钮或 ⌘W 关闭，开着的时候其他窗口照常可用，不另画流程。

流程 2查一处经文并阅读

目标：从任何地方呼出搜索，输入「书卷 + 章:节」，在阅读窗口里读到那一处。

  • 四个入口并不等价：⌥Space 和 Space+P 走 toggle()（见流程 6）；⌘F（文件 → 搜索经文）和菜单栏图标菜单的 打开搜索 (⌥Space / Space+P) 走 show()，只显示不收起；点 Dock 图标只有在没有任何可见窗口时才会显示搜索（applicationShouldHandleReopen 里的 if !flag）。
  • 输入框占位文字：书卷 章:节 例如 yhfy 4:24 · yuehan 3 16 · 约 4:24。查询为空时显示 输入拼音首字母、拼音或中文书名，后面跟 章:节 和一行示例。每敲一个字符就重新搜索，选中项回到第 1 条（SearchViewModel.refresh）。
  • 三个判定依次落在 QueryParser.parse（第一个 ASCII 数字之前是书名，之后必须是「章 [分隔符 节 [- ~ — 至 到 节尾]]」，yh 4:24: 解析失败）、BookMatcher.match（不做模糊匹配；拉丁书名只允许 a–z、*、?，所以 yhfyx、yh fy 4、yh-4 都没有结果）、SearchEngine.search（没有该章或该节的书卷被剔除：yh 4:24 的四卷「约翰」只剩约翰福音；节尾超出本章时截到末节，如 yhfy 4:20-99）。
  • 三种失败显示同一个状态：没有匹配的书卷或章节，下面一行 拼音只按字首/音节前缀精确匹配（不做模糊匹配），* 匹配任意音节，? 匹配一个音节。此时 ⏎ 和 ⌘⏎ 被按键监听吞掉但什么都不做，窗口留在原处。
  • 只写书名（yh）时每卷一行，副标题形如 约 · 21 章，打开的是第 1 章且无高亮；只写数字（4:24）时列出所有含该章节的书卷。排序：完全匹配 → 前缀 → 部分匹配，同级按书卷顺序。
  • 选择：↑ ↓ 与 ⌃N ⌃P 到头即停，不循环。单击未选中的行只是选中，单击已选中的行等于 ⏎；第 1 条默认已选中，所以单击它会直接打开。
  • ⏎ 调 ReaderWindows.open(_, inNewWindow: false)：最前的可见阅读窗口内容被换掉（没有后退），最小化的窗口不算可见，此时会新建一个。随后 SearchWindowController.hide()。阅读窗口标题形如 约翰福音 4:24，所选节加强调色底并滚到顶部。

流程 3同时对照多处经文

目标：把几处经文各放一个窗口并排对照，每个窗口可以独立翻章。

  • ⌘D 是 文件 → 在新窗口打开经文。validateMenuItem 规定：阅读窗口是当前窗口，或搜索窗口在最前且有选中结果时才可用，否则置灰。阅读窗口里的 ⧉ 按钮（plus.square.on.square）悬停提示 在新窗口打开同一处经文 (⌘D)。
  • 从搜索窗口走（⇧⏎ / ⌘D）会顺带隐藏搜索窗口；从阅读窗口走则把当前 passage 原样带到新窗口，高亮也带过去（已翻过章的窗口没有高亮可带）。
  • 新窗口的摆放在 ReaderWindows.place：有可见阅读窗口时取最前那个的尺寸，从它的左上角连续 cascade 两次，落在它右下方而不是正上方；没有时用本次运行中最后关闭的阅读窗口尺寸（lastSize，只存在内存里），都没有则是默认 640×720，屏幕居中。
  • 翻章（ReaderModel.step）只在本卷第 1 章到最后一章之间移动，不跨卷；到头时 ‹ / › 按钮 disabled，← → 没有反应。
  • 翻章后新 Passage 的 verse、verseEnd 都是 nil：高亮消失，窗口标题从 约翰福音 4:24 变成 约翰福音 5，正文滚回第 1 节。

流程 4复制经文

目标：不开阅读窗口，直接把选中的经文连同出处放进剪贴板。

  • 逻辑在 SearchViewModel.copySelected：store.text(for:numbered: r.verse == nil)。查询带节号时每节一行、不带节号；只到章（或只有书名，取第 1 章）时复制整章，每行是「节号 + 空格 + 经文」。
  • 正文之后换行，再加出处行 —— \(reference) (和合本)。例：yh 4:24 得到 
    神是个灵（或无个字），所以拜他的必须用心灵和诚实拜他。
—— 约翰福音 4:24 (和合本)
    节段的出处形如 —— 哥林多前书 13:4-8 (和合本)，整章形如 —— 约翰福音 4 (和合本)。
  • 按键判定在 SearchWindow.swift 的本地监听里：keyCode 36 / 76 且带 ⌘ 即复制，⌘ 的判断先于 ⇧，所以 ⌘⇧⏎ 也是复制。
  • 复制成功没有任何提示，窗口直接隐藏；粘贴前还要自己切回目标 App，见文末第 B1 条。

流程 5收起与退出

目标：看完把窗口收走，但热键继续可用；需要时才真正退出。

  • esc 由搜索窗口的本地按键监听处理（keyCode 53 → hide()）；⌘W 是 文件 → 关闭窗口，对搜索窗口和阅读窗口都有效。applicationShouldTerminateAfterLastWindowClosed 返回 false，关掉最后一个窗口 App 也不退出。
  • ⌘Q 对应的菜单项标题写的就是 关闭所有窗口（保留后台），动作仍是 terminate:，在 applicationShouldTerminate 里被拦下：隐藏搜索窗口、关闭全部阅读窗口，返回 .terminateCancel。Dock 菜单的「退出」走同一条路。
  • 退出好查经（菜单栏图标菜单和「好查经」菜单各一个，没有快捷键）先把 reallyQuit 置为 true 再调 terminate，于是返回 .terminateNow。
  • 系统注销、关机、重启发来的退出 Apple Event 带有 kAEQuitReason，quitRequestedBySystem 据此放行；Dock「退出」发的事件不带这个属性，所以被取消。
  • 收起之后再呼出搜索，上次的查询已被清空（原因见流程 6）。

流程 6热键的切换语义

目标：同一个热键既能呼出搜索，也能把它收走；在搜索框里打字时不被热键打断。

  • SearchWindowController.toggle()：isFrontmost（NSApp.isActive、窗口可见、且是 key window 三者同时成立）为真就 hide()，否则 show()。
  • show() 只在窗口不可见时清空查询并重新定位：移到鼠标所在的屏幕，水平居中，垂直方向比正中高出可视区高度的 12%。窗口可见但被挡住，或 App 不在前台时，保留原查询和位置，只是置前。每次都会 focusToken += 1 让输入框重新获得焦点。
  • Space+P 在好查经自己是活动 App 时被忽略：SpaceChordMonitor.handle 一开头遇到 NSApp.isActive 就原样放行。源码注释给的理由是不干扰自己的搜索框——查询里本来就要打空格（yhfy 4 24）和字母 p，拦截会吞字或让空格迟到。放行的同时清掉挂起状态，免得之后一个过期的 keyUp 被误吞。
  • 由此推出两点：「已在最前则收起」这个分支实际上只有 ⌥Space 走得到；在阅读窗口里也不能用 Space+P 呼出搜索，要用 ⌘F 或 ⌥Space。
  • ⌘F 和菜单栏的 打开搜索 (⌥Space / Space+P) 调的是 show()，不会收起窗口。

流程 7手动停用 / 启用 Space+P

目标：觉得 Space+P 碍事时临时关掉，之后再打开；还没授权时，同一项负责把用户带去授权。

  • 动作是 AppDelegate.toggleChord()：正在运行就 stop()；没在运行就 start()，失败（未授权，或事件 tap 建不起来）则依次 requestPermission()、openAccessibilitySettings()（直接打开「系统设置 → 隐私与安全性 → 辅助功能」，因为系统提示只会弹一次）、waitForPermission()（已经在轮询就不重复起定时器）。最后统一 updateChordMenu()，三种标题见流程 1的表：停用 Space+P 快捷键、启用 Space+P 快捷键、开启 Space+P 快捷键（需授权辅助功能）…。
  • 停用只影响 Space+P，⌥Space 不受影响。这个开关不落盘，下次启动只要已授权就又是启用状态。
  • README 提到 make app 用 ad-hoc 签名，重新构建后授权可能失效，需要在系统设置里删掉旧条目重新勾选；那时走的是「否 → 请求授权、打开系统设置」这一支，勾选之后最多 2 秒自动启用，不用再回菜单点一次。

流程 8Space 键的判定（Space+P 组合键）

目标：启用 Space+P 之后，在别的 App 里照常打空格；用户能感觉到的只有「长按空格会迟一点出来」。

  • 实现在 SpaceChordMonitor.swift（CGEventTap）。Space 的 keyDown 先被吞掉，holdWindow = 0.35 秒内决定去向。P 必须在 Space 还按着、且计时未到时按下才算组合键；超时之后再按 P 就是普通的字母 p。
  • 组合键成立时 Space 和 P 的按下、松开、自动重复全部吞掉，前台 App 什么也收不到，然后在主线程调用 toggle()。
  • 三种「不是组合键」的情形都会补发 Space，顺序不乱：快速点按 → 立刻补发按下和松开；接着按了别的键 → 先补 Space 再补那个键；一直按着 → 0.35 秒到点补发按下，真正松开时的 keyUp 原样放行。补发的事件带一个标记值，tap 再看到它们时直接放行。
  • 只要按着 ⌘ ⌃ ⌥ ⇧ 或 Fn 任意一个就完全不拦截，⌘Space、⌥Space 等系统或其他热键不受影响。好查经自己在前台时同样不拦截（流程 6）。
  • 事件 tap 因超时或用户输入被系统停用时，回调里会把它重新启用。

B. 读源码时看到的可能的 UI 问题

以下是从源码推断的，没有运行 App 验证；标「高」的值得先确认。

#现象原因程度
B1收起搜索窗口后焦点不回到原来的 App。⌘⏎ 复制完要先手动切回去才能 ⌘V；收起后立刻按 Space+P 没反应，要先点一下别的 App。hide() 只 orderOut，没有 NSApp.hide 或重新激活上一个 App，好查经仍是活动 App；而活动期间 Space+P 被忽略。高
B2用中文输入法打「约翰福音」时，选字的 ↑ ↓、上屏的 ⏎、取消的 esc 可能被搜索窗口抢走（移动选中项 / 打开经文 / 收起窗口）。installKeyMonitor 的本地监听先于输入法拿到按键，且没有检查输入框是否有未上屏的候选文字。高
B3复制成功没有任何反馈，窗口只是消失。copySelected 写完剪贴板就 hide()。中
B4⏎ 会覆盖最前阅读窗口里正在读的经文，没有后退；翻章到卷末不能进下一卷。ReaderWindows.open 直接改 model.passage；ReaderModel.step 限定在本卷。中
B5节段写反（yhfy 4:24-20）不报错，被当成单节 4:24。Passage.verseRange 取 max(v, verseEnd)，标题也只在 e > v 时才显示节尾。低
B6⌘↑、⌥↓ 这类带修饰键的方向键也被当作移动选中项，输入框里的光标跳转失效。监听里 keyCode 125 / 126 两个分支不看修饰键。低
